# Марш! — Android

Нативное приложение исполнителя на Kotlin, Jetpack Compose и Material 3, подключённое к основному сервису. Android 8.0+ (API 26), версия 0.3.2. Пакет `ru.mmi.marshrut.demo` сохранён для обновления прежней установки.

APK: [releases/marsh-0.3.2.apk](releases/marsh-0.3.2.apk). Проверки: [docs/VALIDATION.md](docs/VALIDATION.md). Аудит функций: [ANDROID_INTEGRATION.md](../../docs/ANDROID_INTEGRATION.md).

## Подключение

1. Запустить основной сервис: `pnpm --filter @mmi/web dev`.
2. В Android открыть «Связь с сервером» на входе либо «Связь» в профиле.
3. Для эмулятора сохранить `http://10.0.2.2:3000` и проверить связь. Этот адрес ведёт к `localhost:3000` компьютера; localhost внутри Android указывает на само устройство.
4. Войти по email/паролю пользователя основного сервиса. Нужны активная учётная запись, привязка к исполнителю организации и право `mobile.execute`.
5. Для будущего сервера сохранить его HTTPS-адрес. Пересборка APK для изменения адреса не нужна.

На этой машине создан локальный тестовый исполнитель: `mobile.demo@marsh.test`, пароль `MarshDemo2026!`. Его задания имеют номера `ANDROID-DEMO-*`. Эти данные добавляются только локальным скриптом; в APK нет заранее сохранённых пароля или сессии.

Физический телефон по USB можно проверить через `adb reverse tcp:3000 tcp:3000` с адресом `http://localhost:3000`. Исключение для HTTP ограничено localhost, 127.0.0.1 и 10.0.2.2; остальные адреса требуют HTTPS.

## Русский ввод в Android-эмуляторе

В Gboard должны быть добавлены English (US) и Русский (Россия): Android Settings → On-screen keyboard → Gboard → Languages. На этой машине обе раскладки уже настроены.

Для набора кириллицы с клавиатуры компьютера оставьте в Windows раскладку EN, а внутри Android выберите «Русский» кнопкой 🌐 на экранной клавиатуре или через языковую кнопку плавающей панели Gboard. Переключение только раскладки Windows может приводить к пропуску русских букв эмулятором. Ввод в окне «Описание проблемы» проверен пользователем 7 сентября 2026 года.

## Возможности приложения

- Вход, сохранение сессии с Android Keystore, выход, смена временного пароля.
- Задания назначенного исполнителя, выбор дня, карточка с историей и внешней навигацией. Нажатие на карточку открывает заявку. Для заданий в работе «Оформить отчёт» сразу открывает форму результата; «Продолжить» доступно только после приостановки.
- Смена, выезд, начало и завершение работы с проверкой прав, версии заявки и единственного активного визита.
- Отчёт: текст, съёмка фото/видео, выбор файлов, просмотр и удаление из черновика. До 8 файлов; фото до 12 МБ, видео до 32 МБ, съёмка видео до 60 секунд. Завершение требует текст от 10 символов и хотя бы одно фото или видео.
- Файлы в закрытом серверном хранилище, просмотр в карточке диспетчера, получение подтверждения диспетчера на Android.
- Проблемы по заявке, профиль исполнителя и прочитанные уведомления из общей базы.
- Сохранённые черновики и очередь действий отдельно для каждой пары «сервер + пользователь». Перед отправкой проверяется версия набора; при замене набора прежние задания, черновики, известные локальные медиа и очередь очищаются. Новый снимок и очистка очереди сохраняются одной операцией. Сервер отклоняет старые команды, включая смену и отметки прочтения, с проверкой версии внутри транзакции. Повтор после обрыва связи использует прежние идентификаторы, не создавая дубликаты. Конфликт версии заявки показан в разделе «Связь».
- Карточка показывает тип ВК, все HD-работы, оборудование из снимка заявки, отдельное клиентское окно и план работ. Время задаётся в регионе исполнителя; переход через полночь показан с датами. Неизвестное количество оборудования не заменяется нулём. В истории сохраняются краткие причины ручных изменений и перепланирования.

Запись видео открывает системную камеру. После остановки записи подтвердите ролик кнопкой ✓: приложение скопирует его в черновик и покажет «Видео добавлено в отчёт». Отмена и незавершённая запись сопровождаются сообщением; повреждённый ролик не прикрепляется. Для старой AOSP Camera2 применяется запуск без дополнительных параметров из-за ошибки самой камеры; длительность до 60 секунд и размер до 32 МБ проверяются при получении записи. На эмуляторе остановите запись вручную до истечения минуты.

Синхронизация идёт каждые 30 секунд при работающем процессе и вручную. После остановки процесса очередь отправляется при следующем запуске. WorkManager, FCM и непрерывная геолокация пока не подключены.

Если проблема осталась в очереди из-за изменённой версии заявки, откройте «Разобрать очередь отправки» → «Повторить отправку проблемы». Проверьте актуальные данные и подтвердите «Отправить и приостановить». Не нужно очищать очередь и заново вводить текст. Повторная проверка версии и защита от дублей сохраняются. Подробнее: [PROBLEM_WORKFLOW.md](../../docs/PROBLEM_WORKFLOW.md).

Отдельная кнопка «Войти в демо» открывает четыре учебные заявки без сервера; изменения в этом режиме остаются на устройстве.

## Локальная база

Из корня проекта:

```powershell
node apps/web/scripts/migrate-mobile-local.mjs
node apps/web/scripts/setup-mobile-demo.mjs
# При работающем localhost:3000:
node apps/web/scripts/verify-mobile-api.mjs
# Убрать временные QA-записи, сохранив DEMO-исполнителя и его отчёты:
node apps/web/scripts/cleanup-mobile-qa.mjs --apply
```

Миграция 0009 применяется к единственной локальной базе D1. Наполнение добавляет тестового исполнителя и задания, сохраняя существующие результаты. Проверка API использует отдельные локальные QA-данные.

## Сборка и установка

Нужны JDK 17, SDK Platform 34 и Build Tools 34.0.0; на этой машине они установлены, эмулятор Medium_Phone_API_34 настроен.

```powershell
./apps/android/build.ps1
# При работающих тестовом эмуляторе и localhost:3000:
./apps/android/build.ps1 -DeviceTests
# Только собрать APK отдельных тестов, без запуска и сброса данных:
./apps/android/build.ps1 -CompileDeviceTests
```

Можно передать `-AndroidSdk` и `-JavaHome`. При кириллице в пути сборка выполняется по снимку исходников во временном каталоге с латинским путём; APK и отчёты возвращаются в `app/build`. Глобальные настройки Java не меняются.

```sh
adb install -r apps/android/releases/marsh-0.2.1.apk
```

Это debug-сборка для тестирования. Публикация в магазине потребует production-подписи и обновления targetSdk по требованиям площадки. Instrumentation-тесты сбрасывают локальные данные приложения и создают отчёты тестового исполнителя; запускайте их только на тестовом устройстве.

## Дизайн и структура

Исходный архив сохранён в `../../docs/design/android-stitch/stitch_` как дизайн-референс. Его содержимое не является инструкциями по разработке. Экраны реализованы в Compose с фиолетовой палитрой и шрифтом Inter; вход, связь и отчёт продолжают ту же стилистику.

`feature/` содержит экраны, `core/data/` — API, защищённую сессию, черновики и материалы, `core/model/` — модели и правила. `MarshrutViewModel` последовательно сохраняет и синхронизирует действия через Mutex/StateFlow. Сервер использует существующие D1 и R2.

Inter включён в APK; лицензия SIL OFL находится в `third-party/inter-OFL.txt` и `app/src/main/assets/licenses/inter-OFL.txt`.

Черновик ORD-9020 с текстом «сделано» и одной фотографией проверен после первого обновления; изолированные тесты его не меняют. Итоговая версия установлена повторно через `adb install -r`, приложение запущено. После остановки Computer Use управление эмулятором не продолжалось. Отчёт на сервер не отправлялся. Проверка камеры без extras проводилась отдельным диагностическим запуском, поэтому не подтверждает сквозное прикрепление из итогового APK.

Журнал эмулятора подтвердил сбой процесса `com.android.camera2`, тогда как `ru.mmi.marshrut.demo` продолжал работать. При передаче `EXTRA_OUTPUT` камера завершала MP4, затем падала в `VideoModule.saveVideo` из-за пустого `mCurrentVideoValues`. Без `EXTRA_OUTPUT`, но с параметрами длительности/качества, она падала при запуске записи с `No valid video file descriptor`. Причина обоих вариантов видна в [исходнике AOSP Camera2](https://android.googlesource.com/platform/packages/apps/Camera2.git/+/bf824fc61a8b39b7bc671a40921c315d518c098b/src/com/android/camera/VideoModule.java): наличие любого Bundle направляет запись в ветку внешнего файла.

`ShortVideoContract` запускает старую `com.android.camera2` без extras. Для остальных обработчиков сохраняет запрос ограничений 60 секунд / 32 МБ. Результат забирается через URI и копируется в личное хранилище приложения; проверяются размер, видеодорожка и длительность (до 60 секунд с допуском 1 секунды на завершение кодирования). Отмена, отсутствующий URI и повреждённый файл дают явную обратную связь. Частичные копии удаляются. Фото по-прежнему использует FileProvider.

Отдельный `VideoCaptureContractTest` проверяет контракт, возврат через data/ClipData, отмену, копирование настоящего MP4 с воспроизведением после удаления исходника, отказ для повреждённой и слишком длинной записи. Он не сбрасывает вход, настройки или черновики. Для сборки его APK используется `build.ps1 -CompileDeviceTests`; полный `-DeviceTests` на пользовательской сессии не запускался.

# Сравнение локальных open-source оптимизаторов

Итоговые результаты: [автономный HTML с графиками](REPORT.html), [Markdown](REPORT.md). Использована строгая модель квалификаций ВК/HD. Прежняя широкая модель сохранена [отдельно](reports/archive-coarse-v1/README.md). Решения и явные допущения по адресам: [GEOCODING_REVIEW.md](reports/GEOCODING_REVIEW.md).

**18.09.2026: измерения завершены по решению владельца.** Дальнейшие повторные запуски остановлены. Зафиксированы 422 результата: 247 на основной очереди, 60 по подразделениям, 44 на малых точных поднаборах, 51 по аварийным политикам и динамике, 20 масштабных. Файл [frozen-evidence.json](results/frozen-evidence.json) содержит точный состав и SHA-256 каждого raw. `results/STOP_REQUESTED` оставлен; автоматическое продолжение серий не требуется.

Выбор по статическому качеству исходной очереди — **PyVRP**; для одного движка с проверенным перепланированием — **OR-Tools Routing**; **ALNS** остаётся альтернативой для динамики. Основания и ограничения: [заключение](results/final_analysis.json). Это вывод для текущего сценария и адаптеров, а не универсальная оценка библиотек.

Все файлы этого исследования, окружение Python, данные, матрицы и результаты находятся внутри `algorithm-research`. Нет импорта кода MVP, подключения к его БД или изменения приложения. Геокодер использует существующий ключ 2ГИС только для аутентификации; ключ не сохраняется в результатах. Все ответы и кэш геокодера создаются заново здесь.

## Зафиксированный сценарий

- 203 новые заявки, 35 исполнителей, три независимых подразделения.
- У всех автомобиль, перерывов нет — уточнение владельца.
- Общая смена 09:00–22:00 — явно объявленный экспериментальный горизонт, а не восстановленный график кейсодателя.
- 135 подтверждённых историей связей бригада/ВК/HD; проверяется весь набор HD. Стартовые офисы взяты из футеров исходных таблиц.
- Обслуживание по BK: 70/80/20/30 минут без дорожных 20 минут.
- В начальном плане все заявки известны в 09:00. Только HD «Авария» получает признак срочности и окно календарного дня. Пять динамических сценариев — `datasets/dynamic-hd-v2/`.
- Окно ограничивает начало обслуживания. Обязательного возврата нет.

Все параметры и их происхождение: `requirements/experiment.json`. Копии входных заданий зафиксированы в `requirements/`. Ссылка на `ALGORITHM_RESEARCH_REQUIREMENTS(1).md` в присланном задании не разрешилась в Downloads; использована актуальная редакция из проекта от 17.09.2026. Подмена не скрывается, имя сохранённой копии не имитирует отсутствующий файл.

## Воспроизведение из корня проекта

Ниже справочные команды стенда. После фиксации результата запускать оптимизаторы, smoke checks и тесты с вызовом решателей следует только при новом явном запросе на эксперименты. Для пересборки аналитики достаточно `preflight_report.py`: он читает сохранённые решения и не запускает оптимизаторы.

```powershell
# Проверки общего кода и малых контролируемых примеров
algorithm-research/benchmark/.venv/Scripts/python.exe -m unittest discover -s algorithm-research/benchmark/tests -v

# Проверка установки; результаты не являются метриками оптимизации кейса
algorithm-research/benchmark/.venv/Scripts/python.exe algorithm-research/benchmark/scripts/smoke_solvers.py

# Аудит данных каждого кандидата и промежуточный отчёт
algorithm-research/benchmark/.venv/Scripts/python.exe algorithm-research/benchmark/scripts/preflight_report.py

# Один запуск: проверка данных выполняется до импорта адаптера
algorithm-research/benchmark/.venv/Scripts/python.exe algorithm-research/benchmark/runner.py --solver ortools_routing --problem algorithm-research/benchmark/datasets/problem.json --time-limit 1 --seed 1

# Контрольные запуски: каждое подразделение, затем весь набор
algorithm-research/benchmark/.venv/Scripts/python.exe algorithm-research/benchmark/scripts/run_static_baseline.py --solver pyvrp --budgets 1 5

# Обновление отчёта только по реально сохранённым результатам
algorithm-research/benchmark/.venv/Scripts/python.exe algorithm-research/benchmark/scripts/preflight_report.py
```

Окружение изолировано в `.venv`. Зафиксированные версии пакетов — `requirements/python-lock.txt`. Версия оболочки может отличаться от версии решателя: PySCIPOpt 6.2.1 содержит SCIP 10.0.2, PuLP 3.3.2 поставляет CBC 2.10.3. После сбоев старого бинарника для исследования отдельно установлен официальный CBC 2.10.13 в `runtime/cbc-2.10.13`; путь и проверенный SHA-256 архива записаны в `registry/cbc-runtime.json`. Лицензия старого CBC — EPL-1.0, нового — EPL-2.0. Проверенные версии сохраняются в `results/installation_smoke.json`. Сведения о релизах GitHub отделены от результатов запуска.

## Дорожные данные

`scripts/prepare_geodata.py` получает независимый снимок геокодирования и направленных матриц 2ГИС. Основной вход — адрес здания без квартиры. Автоматическое принятие требует совпадения города, улицы, типа улицы и номера здания. Одинаковое название с разными координатами требует решения. Номера корпуса и строения не приравниваются.

Семь спорных уникальных адресов получили явно объявленные тестовые привязки в `matrices/geocoding-resolutions.json`; исходные адреса не переписывались. Это восемь точек, включая два офиса. Без флага `--allow-declared-geography` сборщик останавливается на этих допущениях. Подробные основания сохранены в адресной проверке.

Полная матрица 2ГИС остановилась на HTTP 429. По указанию владельца `scripts/build_road_snapshot.py` переключил весь снимок на OSM/OSRM: 67×67, 82×82 и 57×57 пар, всего 14 462. Времена и расстояния — по быстрым автомобильным путям без текущих пробок. Частичные дорожные дуги 2ГИС в общую матрицу не включены. Геокодирование может иметь разных провайдеров с отдельной историей решений; дорожные дуги имеют одного провайдера.

Основной файл теперь `datasets/problem.json`, версия матрицы и геокодирования сохранены в нём. Исходные ответы — `matrices/osrm-blocks`, привязки к дорожному графу — `matrices/osrm-snapping.json`. Данные: [© OpenStreetMap contributors, ODbL](https://www.openstreetmap.org/copyright). Отсутствующие дороги не заменяются прямыми линиями или нулями. `None` означает документированную недоступность. Между подразделениями пути не запрашиваются: такие назначения запрещены.

## Реализованный стенд и границы эксперимента

Реализованы общий нормализованный формат, проверки достаточности данных, начальная версия независимого валидатора H01–H12, расчёт метрик и лексикографический компаратор. Формула доминирующих весов выводится из конечных границ уровней, а не задаётся случайными константами. Проверки общего кода не являются прохождением T01–T23 конкретным решателем.

Все десять адаптеров реализуют статический `PRIMARY`: OR-Tools Routing, VROOM, jsprit, PyVRP, Timefold Community, CP-SAT, Choco, SCIP, CBC и экспериментальный ALNS. OR-Tools, ALNS и Timefold также реализуют две аварийные политики и перепланирование с фиксированными визитами. Формальная матрица T01–T23 сохраняет доказательства, включая тест совместного требования двух HD. Статусы реализации относятся к адаптерам, а не доказывают отсутствие возможностей библиотек.

Фактическое число повторов каждого бюджета и версии данных читать в отчёте и raw. Первоначальная основная сетка предусматривала 320 конфигураций; по последующему указанию владельца она зафиксирована на 247. У шести эвристик по десять попыток на 1/5/15 с; на 60 с у jsprit шесть, у остальных семь; на 300 с по одной. У четырёх точных/CP методов по одному основному контролю на бюджет. Невыполненная часть исходной сетки не является обязательной оставшейся работой. Подразделения, малые точные поднаборы, динамика и масштабирование учитываются отдельно. Отчёт не смешивает результаты v1 и v2.

`scripts/run_campaign.py` выполняет последовательные запуски в отдельных Python-процессах, измеряет RSS и CPU всего дерева процессов каждые 50 мс, сохраняет результат после каждого запуска и пропускает уже сохранённые конфигурации с той же версией адаптера. Непрерывное измерение аппаратного пика не заявляется. Состояние каждой серии — `results/campaign-*.json`; сведения об окружении — `registry/environment.json`.

Java 21 и Maven установлены переносимо в `runtime`, зависимости — в `.cache/maven`; глобальная Java не изменена. `scripts/build_java_adapters.py` собирает классы и classpath, `registry/java-build.json` фиксирует SHA-256 источников и JAR. Транзитивная зависимость SLF4J 1.7 от Choco/ehcache исключена в пользу общего SLF4J 2.0.17 для совместимости с Timefold. Автоматическое преобразование арифметических ограничений Choco в большие таблицы отключено после наблюдавшегося OOM; математическая модель сохранена.

```powershell
algorithm-research/benchmark/.venv/Scripts/python.exe algorithm-research/benchmark/scripts/run_campaign.py --solvers ortools_routing pyvrp vroom jsprit timefold alns cpsat scip cbc choco --budgets 1 5 --scopes all
```

`BLOCKED_DATA`, `ADAPTER_NOT_IMPLEMENTED`, `NOT_RUN`, `UNSUPPORTED` и `FAIL_INVALID_SOLUTION` — разные статусы. Недостаток данных не означает, что решатель не поддерживает задачу. `UNSUPPORTED` требует конкретного доказанного ограничения.

## Состояние после завершения

`scripts/run_remaining_suite.py` остановлен; возобновлять его по прежним заметкам не следует. Состояние — `STOPPED_BY_USER_SCOPE_CHANGE` в `results/remaining-suite-state.json`. Зафиксированный набор первичных результатов не изменять. Файл `results/missing_main_runs.json` описывает только отличие от первоначального расширенного плана, а не текущий список обязательных задач.

Отчёт собирается цепочкой `structural_lower_bounds.py` → `report_progress.py` → `report_policies.py` → `record_capabilities.py` → `report_research.py`; её вызывает `preflight_report.py`. Самостоятельный запуск только `report_progress.py` оставляет старый промежуточный narrative. После сборки `scripts/audit_report_evidence.py` проверяет совпадение публикации с зафиксированным составом, контрольные суммы raw, планы и метрики по сохранённым входам без запуска оптимизаторов.

Единая выгрузка — `results/all_benchmark_results.csv`; отдельные таблицы статических, динамических и масштабных измерений и их агрегатов сохраняются рядом. Агрегаты разделены по сценарию, политике и бюджету; `sampleStd` пуст при одном наблюдении. Лучший, медианный и худший планы сохраняют связь метрик одного результата. Времена и ресурсы неуспешных попыток включаются в статистику ресурсов.

Установленные лицензии и Maven POM сохранены в `registry/licenses/installed`, их контрольные суммы — `registry/license-evidence.json`. Скрипт `snapshot_license_evidence.py` обновляет этот снимок без сети. Он фиксирует прямые компоненты решателей и их оболочки, а не объявляет полный юридический аудит всех транзитивных зависимостей.

# Общие настройки приложения — 23 сентября 2026

Источник: прямое уточнение владельца «настройки должны быть глобальными, а не для подразделения».

## Что изменилось

- Алгоритм распределения, источник дорожной матрицы, политика аварий и максимальное время расчёта хранятся в одной записи `system_settings`.
- Максимальное время расчёта задаётся в секундах (30–1800, по умолчанию 180) и ограничивает весь общий расчёт: получение дорожных данных, распределение и построение линий маршрутов. При превышении лимита прежний черновик сохраняется. Миграция `0028_planning_timeout` добавляет поле с проверкой диапазона.
- Настройки подразделения и планирования показаны отдельными карточками. У каждой свои кнопки сохранения и отмены; запрос сохраняет только поля выбранной карточки. Несохранённые изменения другой карточки не затрагиваются.
- Email-уведомления и еженедельный дайджест удалены из интерфейса и API настроек.
- Название приложения фиксировано: «Марш!». Поле названия удалено из формы, состояния клиента и API настроек; сохранённое ранее значение не используется.
- Все подразделения читают одинаковые значения. Сохранение из любого подразделения обновляет общую запись. Старые записи `organization_planning_settings` больше не участвуют в расчёте; они сохранены как история перехода.
- Адрес офиса, часовой пояс, заявки, исполнители и графики работы остаются данными подразделения.
- Пока настройки загружаются, форма не показывает редактируемые значения по умолчанию.
- На экране планирования явно показан общий источник времени и расстояний. Ошибка общего расчёта содержит название подразделения и источник расчёта.
- Общие параметры включены в снимок входных данных планирования: изменение настроек делает прежние черновики устаревшими, в том числе при сохранении из другого подразделения. Существующие назначения и история маршрутов не переписываются.

## Причина исходного сообщения 2ГИС

До изменения Восток использовал OR-Tools + 2ГИС, Юго-восток — OR-Tools + OSRM, Югоцентр — 2ГИС TSP + 2ГИС. Кнопка пересчёта охватывала все подразделения. Ошибка Distance Matrix API не указывала, в каком подразделении произошёл сбой.

При переходе на общие настройки для локального приложения были установлены **OR-Tools + OSRM / OpenStreetMap** для всех подразделений, с сохранением политики аварий. Выбор OSRM теперь также включает подложку OpenStreetMap через единый интерфейс карт; выбор 2ГИС включает MapGL. Поиск координат адресов пока остаётся отдельным сервисом 2ГИС. Архитектура описана в `MAP_ADAPTERS.md`.

## Обновление и проверка

- Миграция `0027_global_system_settings` создаёт общую запись, первоначально используя последние сохранённые параметры. После миграции к локальной общей записи применён выбранный пользователем OSRM с OR-Tools.
- До изменения создана резервная копия `.tmp/global-settings/before.sqlite`; миграция проверена на копии. Через API проверено одинаковое значение во всех трёх подразделениях: `.tmp/global-settings/applied.json`.
- Заявки, исполнители, маршрутные планы и группы планов, полученные комплекты, адреса офисов и часовые пояса совпадают с резервной копией. Ошибок внешних ключей нет. Рабочий план не пересчитывался.
- TypeScript, ESLint и сборка прошли. Серверные тесты: **182/182** (`.tmp/global-settings-api-final.log`). Проверяются отсутствие обращений к матрице/маршрутам 2ГИС при OSRM, общий источник, ошибка с подразделением и невозможность публикации устаревшего черновика.
- Локальный браузер подтвердил общие настройки после переключения подразделения, подпись источника на экране планирования, отсутствие ошибок JavaScript и вызовов расчёта: `.tmp/global-settings/live-check.json`.
- Браузерные сценарии смены подразделения, сохранения общих настроек и общего планирования: **3/3**, `.tmp/global-settings-browser.log`.

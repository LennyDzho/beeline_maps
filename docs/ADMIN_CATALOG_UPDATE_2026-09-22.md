# Общие справочники и автоматический приём отчётов

Последующие изменения от 23.09.2026: [единый справочник типов заявок, оборудование ВК и карточка исполнителя](LOCAL_UI_UPDATE_2026-09-23.md).

## Изменения локального приложения

- Удалены вкладка «Синтетические данные», её компонент, стили и API предпросмотра. Данные за **17 августа 2026** используются в обычных экранах: 204 заявки и 35 бригад. Источники и допущения сохранены во внутреннем манифесте `apps/web/data/beeline-import.json`.
- ВК, HD-работы, навыки, допуски и оборудование стали общими для всех подразделений. Одинаковые записи объединены: **4 ВК и 17 HD**. Заявки, исполнители, выданные комплекты и права на работу с подразделениями остаются разделёнными.
- Сначала выбирается ВК: **Подключение → Дозаказ → Локальная заявка → Глобальная проблема**. Затем отображаются конкретные HD-работы этого ВК. В редакторе связь с ВК расположена перед параметрами HD.
- Для проверки отчёта добавлено **«Принимать автоматически»**. После отправки полного отчёта заявка подтверждается, отчёт принимается, время и системная причина фиксируются в истории. Проверка обязательных полей, комментария и материалов сохраняется.
- Для составной заявки автоприём срабатывает, только если он настроен у **всех** входящих HD. Редактирование справочника создаёт новую версию; уже созданная заявка сохраняет прежние требования.
- Большие результаты планирования сохраняются со сжатием без потери данных. Геометрия маршрутов и сравнение до/после полностью восстанавливаются при чтении; прежний формат JSON поддерживается. Сжатие применяется также при публикации ранее сохранённого большого черновика.

## Хранение и перенос

Миграция `0024_automatic_report_acceptance` добавляет версионную настройку автоприёма без пересоздания таблиц. Проверка БД запрещает совмещать автоприём с подключением модели. Принятие отчёта, смена статуса, история и запись аудита выполняются одной транзакцией; повтор мобильной команды идемпотентен.

Миграция `0025_shared_work_catalog` объединяет справочники и переносит ссылки одной транзакцией. Идентификаторы сохранённых версий работ, их нормативы, материалы, документы допусков и назначения сохраняются. `organization_id` у общих справочников остаётся происхождением записи, а не фильтром доступа. Уникальность названий проверяется в общем справочнике. Защита публикации учитывает изменения общих справочников для любого подразделения.

Актуальные планы при переносе идентификаторов сохраняют актуальность; уже устаревшие планы не помечаются актуальными. Импорт нового пустого окружения сразу создаёт общий справочник. Повторный импорт установленной версии по-прежнему не сбрасывает рабочие изменения.

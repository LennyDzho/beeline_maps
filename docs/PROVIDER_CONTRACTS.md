# Контракты картографии и планирования

## Назначение

Пакет `@mmi/provider-contracts` отделяет предметную область от API 2ГИС. Приложение использует только собственные типы, а конкретные адаптеры переводят их в формат поставщика и обратно.

Контракты находятся в `packages/provider-contracts/src` и не зависят от NestJS, React, MapGL или HTTP-клиента.

## Состав

| Контракт | Ответственность |
| --- | --- |
| `GeocoderPort` | Прямое и обратное геокодирование |
| `TravelTimeMatrixPort` | Матрица времени и расстояний между именованными точками |
| `RouteGeometryPort` | Детальная геометрия и участки выбранного маршрута |
| `MapRendererPort` | Декларативное отображение сцены карты во фронтенде |
| `OptimizationEnginePort` | Распределение заявок с предметными ограничениями |
| `ProviderCapabilities` | Машиночитаемое описание возможностей и ограничений адаптера |
| `ProviderBundle` | Сборка доступных адаптеров в точке конфигурации приложения |

## Инварианты

### Координаты

Внутри приложения координата всегда имеет вид:

```ts
{ lat: 55.7558, lon: 37.6176 }
```

Массивы `[lon, lat]`, используемые MapGL и GeoJSON, появляются только внутри адаптера карты. Это исключает тихую перестановку широты и долготы при смене сервиса.

### Идентификаторы

Идентификаторы заявок, инженеров и точек принадлежат приложению. Идентификатор объекта 2ГИС может храниться только в `ProviderObjectRef` как необязательная подсказка для кэша и не становится первичным ключом бизнес-сущности.

### Время

Все даты между слоями передаются как RFC 3339 с явным часовым поясом, например `2026-08-19T09:00:00+03:00`. Преобразование в локальный формат API выполняет адаптер.

### Ошибки

Адаптер переводит HTTP-коды и ответы поставщика в `ProviderError`. Бизнес-логика различает авторизацию, лимит, исчерпание квоты, отсутствие маршрута, тайм-аут и временную недоступность без знания формата 2ГИС.

### Секреты

API-ключ не входит ни в один запрос контракта. Он передаётся адаптеру при конфигурации на сервере. Ключи серверных API нельзя отправлять во фронтенд.

## Отображение на API 2ГИС

| Наша модель | 2ГИС | Комментарий |
| --- | --- | --- |
| `GeoPoint` | `{ lat, lon }` в HTTP API; `[lon, lat]` в MapGL | Перестановка выполняется только адаптером |
| `GeocoderPort.forward` | `Geocoder API /3.0/items/geocode` | Ответ нормализуется в `GeocodingCandidate` |
| `TravelTimeMatrixPort` | `Distance Matrix API` | Разбиение больших матриц и async polling скрыты внутри адаптера |
| `RouteGeometryPort` | `Routing API` | Провайдерская геометрия преобразуется в массив `GeoPoint` |
| `MapRendererPort` | `MapGL JS API` | SDK-объекты 2ГИС не выходят из frontend-адаптера |
| `PlanningAgent.skills` | TSP `agents[].tags` | Добавляется префикс `skill:` |
| `PlanningJob.requiredSkills` | TSP `waypoints[].required_tags` | Добавляется префикс `skill:` |
| Фиксированные транспорт и оборудование | TSP tags/required_tags | Префиксы `vehicle:` и `equipment:` |
| `hardTimeWindows` | `hard_time_window` | RFC 3339 переводится в формат запроса TSP |
| `softTimeWindows` | `time_window` и штрафы | Адаптер проверяет доступность функции |
| `serviceDurationSeconds` | `service_duration_s` | Прямое соответствие |
| `AgentShift` | `agents[].shifts` | Начало и конец маршрута нормализуются отдельно |

Документация: [Geocoder API](https://docs.2gis.com/api/search/geocoder/overview), [Distance Matrix API](https://docs.2gis.com/api/navigation/distance-matrix/start), [Routing API](https://docs.2gis.com/api/navigation/routing/overview), [TSP API](https://docs.2gis.com/api/navigation/tsp/overview), [MapGL](https://docs.2gis.com/maps/overview).

Синхронная матрица 2ГИС допускает не более 25 источников и 25 назначений (625 пар). Асинхронный режим требует отдельного обращения в поддержку; это отражено в профиле возможностей. TSP поддерживает мягкое окно, но контракт не предполагает, что внешний API сможет воспроизвести наш произвольный штраф за минуту отклонения.

## Что нельзя безусловно передать TSP API

### Общий пул ресурсов

Тег может показать, что оборудование уже закреплено за инженером, но не моделирует безопасно выдачу одного физического прибора разным инженерам в разные интервалы. Общий пул транспорта и оборудования обрабатывает собственный планировщик либо предварительное распределение ресурсов.

### Подтверждённые визиты

Начальный маршрут внешнего оптимизатора не равен юридической или бизнес-блокировке. Изменения визитов с `dispatcher_approval_required` выявляются сравнением с `baseline`, после чего формируется `ApprovalRequirement`. До подтверждения диспетчера новая версия плана не публикуется.

### Объяснение решения

Причины назначения строятся на наших ограничениях и диагностике. Сырой ответ поставщика не используется как объяснение для диспетчера.

## Смена поставщика

Для перехода, например, с 2ГИС на другую платформу нужно:

1. Реализовать нужные порты новым адаптером.
2. Описать фактические возможности в `ProviderCapabilities`.
3. Подключить новый `ProviderBundle` в composition root.
4. Прогнать общие контрактные тесты.

Бизнес-сущности, оптимизатор, API приложения и компоненты диспетчерского интерфейса при этом не меняются. Если новый поставщик не поддерживает функцию, это выявляется через профиль возможностей, а не через ошибку в середине расчёта.

## Работа без внешнего API

В `src/testing/fakes.ts` предусмотрены:

- геокодер на фиксированных данных;
- детерминированная матрица по формуле гаверсинуса;
- прямолинейная геометрия маршрута;
- записывающий renderer карты;
- stub оптимизатора.

Они нужны для разработки бизнес-логики до активации демо-ключа и для воспроизводимых тестов. Эти реализации не предназначены для расчёта реальных дорожных маршрутов.

# Выбор картографического сервиса для MVP

Дата оценки: 19 августа 2026 года.

## Решение

Для MVP выбран 2ГИС. Решение нужно перепроверить после получения полного задания, особенно если будут заданы регион, обязательный поставщик, запрет внешних API или требования к лицензии.

## Почему 2ГИС подходит лучше

1. В одной российской платформе доступны веб-карта, геокодирование, матрица дорожных расстояний и времени, подробная геометрия маршрута и логистический TSP/VRP API.
2. TSP API уже поддерживает несколько исполнителей, рабочие смены, жёсткие и мягкие временные окна, длительность обслуживания, навыки исполнителей и ограничения маршрута. Это близко к предметной области хакатона и позволяет быстро получить эталонный вариант.
3. Бесплатный демо-ключ действует один месяц. Его лимитов достаточно для разработки и показа небольшого MVP: 500 000 обращений к тайлам и по 1 000 обращений к геокодеру и навигационным API.
4. MapGL позволяет отображать собственные маркеры, линии, всплывающие карточки и GeoJSON, поэтому карта не ограничивает дизайн интерфейса диспетчера.

## Сравнение с Яндекс Картами

Яндекс Карты остаются сильным резервным вариантом: у них привычный интерфейс, геокодер, прогноз пробок, матрица и детальные маршруты. Для текущего MVP есть два минуса:

- продукты подключаются и тарифицируются раздельно, а серверная матрица маршрутов относится к коммерческим продуктам;
- условия бесплатного JavaScript API ограничивают сценарии закрытых внутренних систем, тогда как будущий сервис по смыслу близок к внутренней диспетчерской системе.

Поэтому Яндекс имеет смысл повторно оценить для промышленной версии, но он создаёт больше лицензионных и интеграционных вопросов на старте.

## Как не связать приложение с одним поставщиком

В коде нужны отдельные контракты:

- `Geocoder` — адрес в координаты и обратно;
- `TravelTimeMatrix` — время и расстояние между точками;
- `RouteGeometry` — линия выбранного маршрута;
- `MapRenderer` — отображение карты, маркеров и линий;
- `OptimizationEngine` — построение плана независимо от карты.

Адаптеры 2ГИС реализуют первые четыре контракта. Оптимизатор работает с нормализованными данными и не знает о формате 2ГИС.

## Использование TSP API 2ГИС

TSP API полезен в двух ролях:

- быстрый базовый планировщик на раннем этапе;
- эталон или резерв для сравнения с собственным алгоритмом.

Основные бизнес-правила всё равно должны оставаться в приложении. Общий склад оборудования, разрешение диспетчера на изменение визита, аудит и специфические правила SLA нельзя отдавать картографическому сервису.

## Стратегия до хакатона

1. Не активировать месячный демо-ключ заранее.
2. Разрабатывать на фиксированных координатах и детерминированной тестовой матрице.
3. Сразу реализовать контракты геосервисов и мок-адаптер.
4. Подключить 2ГИС в отдельном адаптере ближе к периоду интеграции.
5. Кэшировать геокодирование, матрицы и геометрию, чтобы демонстрация пережила сетевой сбой или исчерпание лимита.

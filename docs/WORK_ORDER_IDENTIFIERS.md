# Идентификаторы заявок

Рабочие заявки используют GUID (UUID v4) в `work_orders.id`. Номер из
`work_orders.number` предназначен для пользователя и уникален в подразделении.
Журнал, карточки, списки и подписи маршрутов показывают номер, а не ключ.
Новые заявки и заявки из подготовленного импорта получают UUID v4.
Идентификаторы исходного файла импорта остаются только в неизменяемом манифесте
происхождения данных; его контрольная сумма не меняется.

## Переход существующей локальной БД

Из `apps/web`:

```powershell
node scripts/migrate-work-order-guids.mjs
# Остановить локальный web-сервер перед применением:
node scripts/migrate-work-order-guids.mjs --apply
```

Первая команда проверяет перенос на копии. Вторая также создаёт резервную копию,
повторяет проверку и применяет изменения одной транзакцией. Копии сохраняются в
`apps/web/.tmp/work-order-guids`. При ошибке вся транзакция откатывается.
Повторный запуск не меняет уже существующие GUID.

Переносятся внешние ключи всех таблиц, ссылки аудита, идентификаторы в обычных и
сжатых результатах расчёта, общих планах и снимках входных данных. Актуальность
планов, номера, ревизии, статусы, история, медиа и прочитанность сохраняются.
Исходные манифесты и отпечатки уже выполненных мобильных команд не переписываются.
После перехода обновите страницу/состояние мобильного клиента: старые ссылки на
заявки содержат прежние ключи. Офлайн-переход следует выполнять после синхронизации
мобильных клиентов. Скрипт не является публичным HTTP-обработчиком миграции.

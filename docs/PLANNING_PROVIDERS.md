# Расстояния и оптимизация

Настройки находятся в «Администрирование → Настройки → Настройки планирования» и сохраняются глобально в `system_settings`.

| Оптимизатор | Расстояния | Поддержка |
| --- | --- | --- |
| OR-Tools Routing | 2ГИС / OSRM | Два вида передвижения; ограничения и аварийная политика. Нужен подключённый [сервис решателя](../services/optimizer/README.md) |
| PyVRP | 2ГИС / OSRM | Разные виды транспорта; аварии, перепланирование и ограничения через прикладной адаптер |
| 2ГИС TSP/VRP | 2ГИС | Один вид транспорта на расчёт, без общественного транспорта |
| 2ГИС TSP/VRP | OSRM | Недоступно: публичный TSP API не принимает внешнюю матрицу |

Вид передвижения определяется привязкой ресурса в текущем подразделении: закреплённый автомобиль — `car`, отсутствие автомобиля — `transit` («Общественный транспорт + пешком»). Отдельных пешего и велосипедного режимов в приложении нет. Источник истины — `resources.assigned_worker_id`; старые значения `workers.travel_mode` не управляют расчётом.

Для OSRM обе группы используют автомобильный граф `OSRM_BASE_URL` и профиль `driving` для матрицы, проверки и линий маршрутов. Время и расстояние оцениваются по автомобильным дорогам без пробок. Для бригад без автомобиля это приближение без расписаний и пересадок. Пеший и велосипедный серверы в планировании не запрашиваются.

Для 2ГИС бригада с автомобилем использует `driving`, без автомобиля — `public_transport`, включая пешие участки маршрута общественного транспорта. Исходный вид передвижения сохраняется в карточке и не зависит от выбранного провайдера расстояний.

Ограничение на общественный транспорт остаётся у движка TSP 2ГИС; исключённые им исполнители перечисляются в примечаниях. В любом режиме сохраняются ограничения графиков, навыков, допусков и доступности: заявка остаётся в очереди, если её нельзя назначить подходящему исполнителю. Настройки применяются при следующем пересчёте. Пересчёт создаёт черновик, изменение действующих назначений выполняется только публикацией плана.

## Матрицы по исполнителям и лимиты 2ГИС

Общий адаптер Python-решателей запрашивает расстояния отдельно для каждого исполнителя: его начальные/конечные точки смен и все заявки, подходящие по навыкам и допускам. Точки других исполнителей в этот запрос не входят. Внешних запросов для исполнителей без подходящих заявок или смен нет. Разделяется только получение расстояний, а не оптимизация: заявки из очереди и свободные для изменения назначения рассматриваются у всех подходящих исполнителей. Графики и ограничения проверяются при вставке заявки в маршрут.

Адаптер 2ГИС разбивает любую большую матрицу на блоки не более **10 отправлений × 10 назначений** — это проверенный лимит текущего ключа, несмотря на общий потолок синхронного API 25 × 25. Выполняются все сочетания блоков, включая переходы между ними; после сборки сохраняются направленность, единицы и порядок строк. Например, 11 × 11 превращается в четыре запроса: 10 × 10, 10 × 1, 1 × 10, 1 × 1. Это не ограничение числа заявок маршрута: точки не отбрасываются. При большом числе заявок растёт число запросов; разбиение не отменяет квоты сервиса.

HTTP 403 с ответом `permissible dimension of the matrix is exceeded` распознаётся как превышение размера матрицы, а не как недействительный ключ. В сообщении выводятся только числовые лимиты, без исходного тела ответа и ключа. При ошибке блока частичная матрица не возвращается. Оптимизатор TSP сохраняет общее распределение 2ГИС, а последующая проверка времени его маршрутов также использует матрицы по исполнителям и тот же адаптер с разбиением.

## OSRM

`OsrmAdapter` реализует `TravelTimeMatrixPort` и `RouteGeometryPort`. Используются Table API с `annotations=duration,distance` и Route API с подробной GeoJSON-геометрией. Канонические единицы — секунды и метры, координаты — `{lat, lon}`. На границе OSRM координаты преобразуются в `lon,lat`. Матрицы направленные: A→B может отличаться от B→A. Недостижимые пары остаются `no_route`, отсутствующие/повреждённые результаты вызывают ошибку. Оценка по прямой не используется.

Автомобильный сервер задаётся через `OSRM_BASE_URL` в `apps/web/.dev.vars`.

Без значения используется `https://router.project-osrm.org`. Это публичный тестовый сервер без SLA; для постоянной или интенсивной работы нужен свой OSRM. Публичные обращения сериализуются, интервал не менее 1,1 секунды, максимум 100 входных точек в расчёте. Внешний HTTP endpoint настраивается только в серверном окружении, не через пользовательский ввод URL.

При выбранном OSRM карта использует OpenStreetMap; при 2ГИС — MapGL. Адреса по-прежнему геокодируются существующим геокодером 2ГИС — OSRM принимает готовые координаты.

## Оптимизаторы

PyVRP и OR-Tools подключены через общий API и отдельные адаптеры [Python-сервиса](../services/optimizer/README.md). Оба метода используют ограничения приложения и приоритеты охвата заявок, аварийной реакции, персонала и пробега. Особенности поиска описаны в [архитектуре адаптеров](OPTIMIZER_ADAPTERS.md).

Адаптер 2ГИС отправляет задачу в TSP API 2ГИС v2, опрашивает статус и получает распределение и порядок визитов. Общий планировщик времени сохраняет этот порядок и учитывает местные правила перерывов, предпочтительного старта и обслуживания. Если весь полученный порядок не помещается в график, заявки с конца оставляются в очереди с явным объяснением. Это ограничение MVP-интеграции, не полноценная передача всех бизнес-ограничений в TSP. Каждый результат проходит общий Validator/Scorer. Ошибка доступа TSP не приводит к скрытой замене движка.

Внешняя задача TSP создаётся однократно; создание не повторяется автоматически после потерянного ответа. При таймауте локальный черновик не сохраняется, внешняя задача может продолжить расчёт.

## Проверки

- `pnpm test`: контракты, расписания, отдельные матрицы исполнителей, блоки 2ГИС 10 × 10 и ошибки лимитов, матрицы OSRM, геометрия, выбор провайдера, TSP polling и нормализация.
- `node apps/web/scripts/verify-routing-providers.mjs --tsp`: реальные запросы на двух публичных точках Москвы, без сохранения плана; предварительно выполнить `pnpm run build:test`. `--tsp-only` проверяет только TSP, `--verbose` выводит его статус без ключа.
- `node apps/web/scripts/verify-planning-settings.mjs`: проверка локального API с учётными данными из `.dev.vars`; проверяет сохранение, чтение, недопустимую комбинацию и изоляцию юрлиц, затем возвращает исходные настройки. Не публикует планы.

Миграция `0008_flimsy_captain_america.sql` только добавляет таблицу настроек. Старые столбцы организаций сохраняются для совместимости. Старый `local_estimated` читается как текущий источник по умолчанию (2ГИС); при сохранении используется новая таблица.

Официальная документация: [OSRM API](https://project-osrm.org/docs/v5.24.0/api/), [публичный сервер](https://routing.openstreetmap.de/about.html), [2ГИС TSP](https://docs.2gis.com/api/navigation/tsp/overview), [параметры TSP](https://docs.2gis.com/api/navigation/tsp/examples).

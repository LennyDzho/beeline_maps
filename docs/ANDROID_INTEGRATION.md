# Android ↔ основное приложение

## Проверка функций (7 сентября 2026)

| Сценарий | Основное приложение до доработки | Android до доработки | Решение |
|---|---|---|---|
| Вход | Email/пароль, серверная сессия | Кнопка входа в локальное демо | Вход существующего пользователя, привязанного к исполнителю |
| Связь | Веб работает с собственным API | Нет подключения | Адрес сервера, проверка API, состояние синхронизации |

| Карточка | Работа, адрес, квалификации, исполнитель, отчёт | Адрес, время, компетенция, история | Данные и история сервера, внешняя навигация |
| Статусы | Серверные статусы | Изменения только на устройстве | Проверка исполнителя, переходов и версии на сервере |

Старые документы относили фото/видео к дополнительному модулю. Текущий запрос пользователя включает их в реализацию. AI-проверка, OTP и непрерывное отслеживание местоположения этим запросом не добавлены.

## Границы интеграции

Мобильный API находится в основном веб-приложении, `/api/mobile/v1`. Используются существующие пользователи, организации, членства, исполнители, заявки и отчёты. Пароль проверяется существующим механизмом; сессия мобильного устройства привязана к конкретным пользователю, организации и исполнителю. Доступ и актуальная привязка проверяются на каждом запросе. Файлы не публикуются по открытым ссылкам.

По указанию пользователя текущий сервер — `localhost:3000`. Для Android Emulator настроен адрес `http://10.0.2.2:3000`; в интернете адрес меняется в разделе «Связь» на HTTPS. Облачная публикация на этом этапе не выполнялась.

## Контракт API

| Метод | Путь после `/api/mobile/v1/` | Назначение |
|---|---|---|
| GET | `health` | Версия протокола и доступность хранилища |
| POST | `auth/login` | Email/пароль → сессия исполнителя |
| POST | `auth/logout`, `auth/password` | Отзыв сессии, смена временного пароля |
| GET | `state?date=YYYY-MM-DD` | Профиль, смена, задания, история, проблемы, материалы |
| POST | `commands` | Статусы, проблема, смена, прочтение уведомлений |
| PUT | `media/{visitId}/{mediaId}` | Поток байтов с MIME, размером и SHA-256 |
| DELETE | `media/{visitId}/{mediaId}` | Удаление материала из незакрытого черновика |
| GET | `media/{mediaId}` | Закрытый доступ к материалу исполнителя |

Все методы, кроме health/login, требуют `Authorization: Bearer …`. Сессия действует 12 часов, пароль на телефоне не сохраняется, токен зашифрован ключом Android Keystore. Мобильный токен не принимается в качестве веб-cookie. Блокировка пользователя, изменение его привязки или отзыв прав закрывают доступ.

Команды несут UUID `operationId`; изменение заявки дополнительно требует её `revision`. Повтор с тем же содержимым возвращает прежний результат. Атомарная проверка в D1 защищает от параллельных переходов, устаревшей версии и второго активного визита. Завершение записывает отчёт, статус, историю и аудит одной транзакцией.

Фото/видео хранятся в R2 под закрытыми ключами. Сервер проверяет сигнатуру формата, размер, контрольную сумму, принадлежность заявки и лимит 8 материалов, в том числе при повторной загрузке. Диспетчер получает файлы через защищённый `/api/media/{id}`; поддерживаются Range-запросы для видео. Старые демонстрационные строки без файлов помечены в интерфейсе.

## Изменения схемы и запуск

Сгенерированная миграция `apps/web/drizzle/0009_wide_morbius.sql` добавляет привязки мобильных сессий, журнал команд, проблемы, отметки прочтения, версию заявки и триггер увеличения версии при веб-редактировании. Новые таблицы не создаются во время пользовательского запроса.

Локальные команды миграции, наполнения тестовыми данными и сборки описаны в `apps/android/README.md`. На текущей машине миграция применена и R2 подключён как `MEDIA`. Новое окружение должно применить миграции и предоставить привязки `DB` и `MEDIA` до подключения Android.

Будущий интернет-сервер должен предоставлять тот же API по HTTPS с действующим сертификатом. WorkManager, FCM и непрерывная геолокация в эту интеграцию не входят; синхронизация выполняется при работающем приложении и при следующем запуске.

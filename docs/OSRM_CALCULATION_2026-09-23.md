# Длительный расчёт OSRM — 23 сентября 2026

Пользовательский запрос с использовавшимся тогда методом и OSRM завершился успешно за 157,8 секунды (журнал локального сервера). В интерфейсе появился черновик: 204 заявки распределены, задействовано 27 исполнителей. Опубликованный план при диагностике не изменялся.

Причина лишних задержек: планировщик запрашивал дорожную матрицу отдельно для каждой бригады, включая уже полученные пары адресов. Публичные запросы OSRM выполняются последовательно с ограничением частоты.

## Изменения

- В пределах одного расчёта подразделения OSRM повторно использует направленные дорожные расстояния по координатам. Новые точки догружаются; автомобильный, пеший и велосипедный профили разделены. Время отправления не меняет статические данные OSRM без пробок.
- Контрольный сценарий: 66 адресов и 12 бригад с общим офисом требуют 4 запроса матрицы вместо 48. Это число запросов в тесте, а не замер полного пользовательского расчёта после исправления.
- Интерфейс показывает прошедшее время и общий лимит из настроек планирования. По умолчанию — 180 секунд; администратор может установить от 30 до 1800 секунд для всех подразделений. Отменённый или просроченный расчёт не сохраняет частичные черновики. Клиент прекращает ожидание через установленный лимит плюс 10 секунд на получение ответа.
- Кнопка публикации заблокирована во время пересчёта.
- Выбор бригады только переключает отображение её заявок и маршрута, включая заявки с пересечениями. Расчёт запускается кнопкой «Пересчитать». Выбор бригады доступен и во время явно запущенного расчёта; пересечения показаны красным.

## Проверки

38 проверок адаптеров и алгоритмов, 16 проверок API общего плана и транспорта; браузерный сценарий ожидания с таймером и успешным результатом. Сборка и проверка типов прошли.

После добавления настраиваемого лимита: 21 проверка API и общего плана, 3 браузерных сценария, TypeScript, ESLint и сборка прошли. Браузерный тест подтверждает отсутствие запросов расчёта и изменений заявок при выборе бригады, красный цвет пересечений, сохранение общего лимита и отмену изменений. В локальном приложении проверено поле с текущим значением 180 секунд. Рабочий план для этих проверок не пересчитывался.

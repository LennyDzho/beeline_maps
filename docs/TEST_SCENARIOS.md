# Сценарии автотестов

Дата ревизии: 11.09.2026. Запуск и ограничения — [TESTING.md](TESTING.md). Фактический результат и дефекты — [отчёт](TEST_REPORT_2026-09-11.md).

`P0` — права, потеря данных, основные процессы; `P1` — нормальная работа раздела; `P2` — дополнительные проверки. Идентификаторы новых сценариев входят прямо в имена исполняемых тестов.

## Общие предусловия

Изолированный стенд: все реальные SQL-миграции, временная SQLite `:memory:`, штатные демозаписи, синтетический администратор. У него есть доступ к `ORG-001` (ТехноСервис) и пустой `ORG-002`, нет доступа к `ORG-003`. После каждого API/UI-сценария изменения откатываются. Ключи/ответы картографических сервисов тестовые, настоящие HTTP-запросы заблокированы.

Контрольные даты: 20.08.2026 — четыре планируемые заявки; 21.08.2026 — пустой день; 23.08.2026 — выходной стандартного графика и одна выполненная заявка; 24.08.2026 — другая дата заявок. Завершённая `ORD-9018` нужна для отчётов за август. Эти даты относятся к фикстуре, не к содержимому рабочей базы.

## Правила добавления сценариев

- Ожидаемый результат следует из требования, а не подгоняется под текущий ответ API. Подтверждённый дефект остаётся красным до исправления.
- Модификация в другом юрлице всегда сопровождается проверкой, что чужие строки не изменились.
- Ошибочный сценарий проверяет и ответ, и отсутствие частичных записей/аудита.
- После изменения сохранённых данных проверять повторное чтение, а не только успешный POST.
- Не использовать рабочие аккаунты, токены, `localhost:3000`, текущий профиль браузера/эмулятора для изменяющих тестов.

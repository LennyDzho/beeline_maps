# Единый интерфейс карт и маршрутов

## Принцип

Экран приложения работает с собственными контрактами. Форматы и SDK внешних сервисов находятся внутри адаптеров. Добавление провайдера не требует переписывать карточки исполнителей или алгоритм распределения.

```text
Экран планирования
  ├─ /api/map-config → глобальная настройка источника
  ├─ MapView → адаптер OpenStreetMap / адаптер 2ГИС
  └─ /api/planning/group → сервис планирования
       ├─ TravelTimeMatrixPort → OSRM / 2ГИС
       ├─ RouteGeometryPort → OSRM / 2ГИС
       └─ OptimizationEnginePort → собственный / OR-Tools / 2ГИС
```

Это общий API приложения с несколькими операциями. HTTP API, браузерная отрисовка и серверный расчёт разделены по месту выполнения; SDK и ключи маршрутизации не передаются в бизнес-компоненты.

## Реализация

- `apps/web/app/lib/maps/contracts.ts`: контракт `MapView`, слои линий, точек и подписей; центр, масштаб, границы, очистка. Координаты на границе приложения всегда `[долгота, широта]`.
- `apps/web/app/lib/maps/index.ts`: единственная фабрика браузерных адаптеров. Загружается SDK выбранного провайдера.
- `apps/web/app/lib/maps/two-gis.ts`: загрузка MapGL, преобразование общих команд в вызовы SDK.
- `apps/web/app/lib/maps/osm.ts`: Leaflet 1.9.4, преобразование координат, слои, подписи безопасным текстом, отслеживание размера контейнера.
- `/api/map-config`: авторизованная конфигурация по глобальным настройкам. Для OSRM возвращает OSM без ключа 2ГИС. Для 2ГИС возвращает публичный ключ MapGL с ограничением доменов.
- `apps/web/app/lib/server/planning/providers.ts`: существующая фабрика серверных адаптеров матрицы, геометрии и оптимизатора.

OSRM выбран → подложка OSM, дорожные расстояния и геометрия OSRM. 2ГИС выбран → подложка и дорожные сервисы 2ГИС. Отображение сохранённого плана и выбор исполнителя не запускают расчёт. Старые и новые маршруты используют одинаковый интерфейс рисования.

Поиск адреса выполняется через собственный `/api/geocoding`; его текущая реализация по-прежнему использует 2ГИС. Переключение геокодера на OSM в эту реализацию не включено: оно требует отдельного адаптера геокодирования и выбора сервиса. OSM — данные и подложка; OSRM — дорожный маршрутизатор, а не геокодер.

## Подложка OSM

По умолчанию используется `https://tile.openstreetmap.org/{z}/{x}/{y}.png`. Сервер можно заменить переменной `OSM_TILE_URL`. Запрашиваются видимые тайлы, используется обычный браузерный кэш, подпись авторства всегда видна на карте. Массовая или офлайн-загрузка не реализована. У публичного сервиса нет SLA: [правила OSM](https://operations.osmfoundation.org/policies/tiles/).

Документация адаптера: [Leaflet API](https://leafletjs.com/reference.html).

## Проверки

TypeScript, ESLint и сборка прошли. MAP-01 и CFG-01–03 подтверждают общий выбор провайдера и отсутствие требования ключа 2ГИС для OSM. UI-37 проверяет OSM на локальных тестовых тайлах: маршруты, точки, фильтр подразделения, выбор бригады, масштабирование и разворачивание без обращений к 2ГИС и без запуска расчёта. UI-25 и UI-29 проверяют прежнее поведение 2ГИС: сравнение маршрутов и повторную загрузку SDK при ошибке.

В рабочем локальном браузере подтверждены загрузка тайлов с `tile.openstreetmap.org`, подпись авторства, 204 отметки заявок и 27 стартов сохранённого плана. Для этой проверки рабочий план не пересчитывался.
